## 포괄적 예외 처리가 서로 다른 버그 두 개를 숨긴 사례

### 문제 상황

로그인 인증 부분(`get_current_user`)을 동기 코드에서 비동기 코드로 바꾸던
중이었다. 코드를 고치고 서버를 켜서 확인하면 항상 401 에러만 떴다. 새로
로그인해서 토큰을 다시 받아 시도해도 마찬가지였다.

```python
try:
    payload = jwt.decode(token)
    ...
except Exception:
    raise credentials_exception
```

### 원인

`except Exception:`으로 모든 에러를 다 잡고 있어서, 진짜 원인이 뭔지 전혀
안 보이는 상태였다. 하나씩 직접 실행해보면서 확인했더니 실제로는 두 가지가
잘못돼 있었다.

첫 번째는 설정값 이름이 잘못돼 있었다.

```python
>>> setting.SECRET_KEY
AttributeError
```

두 번째는 `jwt.decode()`에 필요한 값(키, 알고리즘)을 안 넣고 부르고 있었다.

```python
>>> jwt.decode(token)
DecodeError
```

두 에러 다 `except Exception:`에 걸려서 그냥 "토큰이 잘못됐다"는 401로
뭉뚱그려지고 있었다. 로직 자체가 한 번도 제대로 실행된 적이 없었는데,
겉으로는 그냥 인증 실패처럼 보였던 거다.

### 해결

`except Exception:`을 실제로 예상 가능한 에러 타입으로 좁혔다.

```python
except (jwt.PyJWTError, ValueError):
    raise credentials_exception
```

이렇게 하니 위 두 에러가 숨지 않고 그대로 드러나서 바로 원인을 알 수 있었다.
그다음 설정값 이름을 고치고, `jwt.decode()`에 키·알고리즘을 채워 넣었다.
그리고 정상 토큰, 위조된 토큰, 만료된 토큰, 형식이 잘못된 값을 각각 직접
넣어보면서 의도한 대로만 걸러지는지 하나씩 확인했다.

### 느낀 점

에러 처리할 때 `except Exception`을 습관처럼 썼었는데, 이번에 그게 오히려
버그를 못 보이게 만든다는 걸 직접 겪었다. 지금은 예외 처리를 쓸 때 "여기서
실제로 나올 수 있는 에러가 뭐지"를 먼저 생각하고 그것만 잡으려고 한다.
